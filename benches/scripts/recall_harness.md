# Recall frontier harness (`vbench-genesis`)

Runbook for the recall–latency frontier sweep behind
[`docs/AUDIT--P32-RECALL-500K-FRONTIER.md`](../../docs/AUDIT--P32-RECALL-500K-FRONTIER.md).
Not run in CI — it needs a multi-GB corpus and minutes of build + sweep time. Run
locally when you need fresh numbers.

> All `[[bin]]` targets are gated behind the off-by-default `bins` feature, so every
> command below passes `--features bins`. On Windows/PowerShell, set env vars with
> `$env:NAME = "..."` and ignore the `Load Node-API … failed` stderr lines (the napi
> symbols are absent outside the Node host; the bin still runs).

## 1. Build the corpus (once per scale)

Generate a synthetic-clustered corpus + exact-L2 ground truth with the `synth`
mode of `benches/vbench.py` (rng seed 42 → reproducible). Write the large `.f32`
files OUTSIDE the repo so they are not tracked:

```bash
# 500k example (≈2.05 GB corpus). Pass the node count; use 1000000 / 2000000 for
# higher scales. do_synth writes the corpus/queries/ground-truth for vbench-genesis.
python benches/vbench.py synth 500000
```

For the 500k+ frontier the corpus was generated by a small `gen.py` next to the
corpus dir that mirrors `vbench.py`'s `do_synth` (seed 42) so the 100k set stays
untouched; a matching `score.py` (mirrors `recall_at_k`) scores the output. Reuse
that `gen.py`/`score.py` pair if it already exists beside `$GB_VBENCH`.

## 2. Run the ef_search sweep

```bash
# bash
export GB_VBENCH=/path/to/gb_vbench_500k
export GB_EF=200
export GB_EF_SWEEP="50,100,200,400,800"
cargo run --release --features bins --bin vbench-genesis   # -> $GB_VBENCH/genesis_frontier.json
```

```powershell
# PowerShell
$env:GB_VBENCH = "C:\Users\<you>\gb_vbench_500k"
$env:GB_EF = "200"
$env:GB_EF_SWEEP = "50,100,200,400,800"
cargo run --release --features bins --bin vbench-genesis
```

Build is the slow part (release + LTO, ~2–3 min cold). The HNSW build runs at
`efc = GB_EF`.

## 3. Score recall

```bash
python "$GB_VBENCH/score.py"   # mirrors recall_at_k -> $GB_VBENCH/frontier_results.json
```

`frontier_results.json` holds `{ ef_search, recall@10, p50_us, p95_us }` rows — paste
them into the audit table.

## 4. Quantized + rerank variant (PR #21)

To measure SQ8/BQ recall **with** the f32-sidecar rerank, create the collection with
`quant` + `rerank = true` (via NAPI/REST `create_collection`) and re-run an equivalent
sweep on real embeddings. The baseline `vbench-genesis` path uses the legacy
single-space `Storage::open` (no quant), so a quant+rerank frontier needs a
collection-aware driver — track as a follow-up.

## Gotchas (Windows / bench)

- Always pass `--features bins`; without it the bin target is not built.
- Delete any stale `*.lock` / temp DB dirs from a killed prior run before re-running.
- `Load Node-API … failed` on stderr is expected and harmless.
