# PROPOSAL — HQL Redefinition (Genesis, Fable-5)

> Every perf number below is repo-measured (audit doc cited) or marked `⚠ ungrounded:`. Method: 3 competing designs authored independently, adversarially judged on perf-feasibility / tar-pit / cost-coverage lenses; this is the synthesis. Worklog: `docs/genesis-interview/evidence/`.

## Reality check on §3 targets

**G1 (Qdrant parity / +10%).** Split the bar. *Expressiveness:* reachable for the boolean core — `AND/OR/NOT/parens`, `=/!=/</<=/>/>=`, `IN`-list, `CONTAINS/STARTSWITH` — which covers Qdrant's `must/should/must_not` + `match/range/values-in`. Not reachable in this program: geo filters, nested-object payload paths, full-text `MatchText` (the engine has no lexical leg until substrate S3; the trigram index is fuzzy-id resolution only, lib.rs:2336). Honest renegotiation: "the filter algebra GKS/GoVibe actually emits, with a published gap table." *Latency:* against Qdrant **as deployed** (server, gRPC) the ≥10% win is near-certain for in-process consumers — P20 measured 974 µs vs 3,301 µs p50 unfiltered — but that is a **deployment-category win** (and Qdrant's number was inflated by Docker-on-Windows networking); publish both framings or neither. Against an embedded-equivalent Qdrant kernel we likely **lose**: our build enables no SIMD (Cargo.toml:66 pins `hnsw_rs = "0.3.4"` with default features; the crate *does* ship `simdeez_f`/`stdsimd` features — a one-line, unexplored lever to bench before conceding the kernel gap) vs Qdrant's AVX2/512 kernels, ~4–8×/distance-eval `⚠ ungrounded: kernel ratio from architecture knowledge, not measured here`. No filtered-search comparison exists in-repo at all — G1 currently has **zero evidence base**. Honest target: *parity on vector+filter at ≥1–10% selectivity with recall ≥0.95 (F3 gate); the ≥10% win lives in G3 and in deployment framing, not in the kernel.*

**G2 (Cypher subset within 10%).** The latency bar is not just reachable — it is already **exceeded by 1–2 orders of magnitude** on the shapes GKS/GoVibe needs: hop1 22.6 µs = 120–189× faster than Neo4j/Kuzu/LadybugDB, hop3 6.8–10.5×, hop6 7.2–7.6× vs Neo4j (P23) and ~23× vs Kuzu/LadybugDB (P31, variance-caveated; like-for-like embedded for the Kuzu family). Two honest caveats: the deep-hop numbers carry a payload-materialization confound until lazy bindings land (P29), and margins will shrink in the first true HQL-vs-Cypher head-to-head once both sides return bare ids (possible only after var-length lands — REPORT--HQL-V1-VS-V2 §4.4). Scope honesty: "expressively equivalent" holds only for a **declared subset** — linear patterns, var-length `*min..max`, rel alternation, boolean WHERE, `count(*)`. OPTIONAL MATCH, branching patterns, path variables, shortest-path, general aggregation: permanent non-goals (SPEC--HQL-V2 §7). And the bar excludes the standing losses — bulk ingest (~13× vs Kuzu COPY: 7.8 s vs 0.6 s per P31; it was 48–60× pre-MARK-XIII) and RSS (~7× vs columnar, P31) — which are substrate-S1/bulk-path territory. Anyone reading "G2 met" must see those exclusions.

**G3 (cross-dimension decisive win).** Round-trips: **structural, guaranteed** — 1 in-process call vs ≥3 (Qdrant leg + Neo4j leg + app RRF/join). Latency: a **hypothesis** — fused vector→2-hop→RRF estimated 2–4 ms from measured legs vs a *parallel-leg* composition floor of ~4–5 ms ⇒ ~1.5–2.5×, not the 3–5× naive sum-of-legs arithmetic suggests. No G3-shape benchmark has ever been run; per the honesty clause, "decisive" is defined **before** measuring: ≥1.5× on both p50 and p99 vs the strongest *embedded* composition (LanceDB+Kuzu+in-process RRF), plus the round-trip count, plus the consistency probe. The axis where the win is absolute at any latency: one `AS OF` timestamp applied across vector post-filter (lib.rs:3633) and every BFS edge/node check (:3754/:3789) — inexpressible over Qdrant+Neo4j without building a bespoke bitemporal layer across two stores. If the bench only ties on latency, the moat renegotiates to *expressiveness + consistency + zero-ops*, said out loud.

## HQL v-next surface

Additive over the working-tree grammar (P0 fixes present: search-by-node, K/EF/OVERSAMPLE, DIRECTION, multi-rel). Corrections applied from panel review: seed rule factored so clauses/AS-OF aren't consumed twice; `WIDTH` (per-node breadth) and `FRONTIER` (global row cap, hard error) are **separate keywords**; tier list enumerated (pest can't range string literals); traverse stage optional so a no-hop `RANK BY` query parses.

```pest
query        = { SOI ~ (pipeline | traverse | match_pattern | context) ~ EOI }
pipeline     = { seed_core ~ then_traverse? ~ temporal? ~ rank_by? ~ clauses }
seed_core    = { search_core | hybrid_core }          // search/hybrid WITHOUT trailing as_of/clauses
then_traverse= { ^"THEN" ~ ^"TRAVERSE" ~ ^"REL" ~ (rel | "*") ~ ^"DEPTH" ~ depth_range
                 ~ width_spec? ~ frontier_spec? ~ direction_spec? }
depth_range  = { (depth ~ ".." ~ depth) | depth | h_tier }   // DEPTH 2 | DEPTH 1..3 | DEPTH H2
h_tier       = { "H0"|"H1"|"H2"|"H3"|"H4"|"H5"|"H6" }        // H6 REQUIRES frontier_spec (parse error otherwise)
width_spec   = { ^"WIDTH" ~ number }                  // W-scale per-node/per-hop cap, deterministic truncation
frontier_spec= { ^"FRONTIER" ~ number }               // global frontier row cap, HARD ERROR on breach (SPEC-V2 §3.2)
temporal     = { as_of2 | during }
as_of2       = { ^"AS" ~ ^"OF" ~ string_lit ~ (^"SYSTEM" ~ string_lit)? }   // valid-time [+ tx-time]
during       = { ^"DURING" ~ "[" ~ string_lit ~ "," ~ string_lit ~ ")" }     // valid-time overlap, closed-open
rank_by      = { ^"RANK" ~ ^"BY" ~ ^"rrf" ~ "(" ~ (^"k" ~ ":" ~ k ~ ",")? ~ sig ~ ("," ~ sig)* ~ ")" }
sig          = { (^"vector" | ^"hops" | ^"recency" | prop_field) ~ ":" ~ number }
// WHERE upgrade (all commands): expr = term (OR term)* ; term = factor (AND factor)* ;
// factor = [NOT] (predicate | in_list | "(" expr ")")          — per SPEC--HQL-V2 §4.1 + NOT/IN
// patterns: rel_detail gains ("*" ~ depth ~ ".." ~ depth)? and rel alternation  — SPEC-V2 §3.1/§3.4
```

Examples:
1. `SEARCH doc-7 K 10 EF 200 IN gks WHERE (prop.status = "active" OR prop.status = "review") AND NOT prop.archived = "true"` — G1 shape; WHERE compiles to a pre-filter bitmap, pushed into ANN.
2. `MATCH (a {id:"g0"})-[:LINK*1..6]->(b) FRONTIER 100000 RETURN b.id LIMIT 1000` — the P26/P30 bench query, first-class.
3. `TRAVERSE FROM ~"FEAT--TAX-DEDUCT" DEPTH H2 REL depends_on|blocks DIRECTION both WIDTH 5 LIMIT 500` — `query_genesis_graph` with W2 governance.
4. `TRAVERSE FROM roadmap-42 DEPTH 1 REL contains DURING ["2026-06-01T00:00:00Z","2026-07-01T00:00:00Z")` — sprint-window overlap (ERD).
5. `TRAVERSE FROM task-77 DEPTH 2 REL assigned_to AS OF "2026-06-15T00:00:00Z" SYSTEM "2026-06-20T00:00:00Z"` — two-axis point.
6. `MATCH audit-seed ALPHA 0.0 K 40 IN gks THEN TRAVERSE REL depends_on|caused_by DEPTH 1..2 WIDTH 8 AS OF "2026-07-01T00:00:00Z" RANK BY rrf(k:60, vector:1.0, hops:0.5, recency:1.2, prop.confidence:0.8) LIMIT 20` — the G3 moat query, one round-trip.

Semantic contract (the parts that keep us honest): `SYSTEM` applies to **edges only** — nodes carry no `recorded_at` (NodeOutput) and `supersede_node` overwrites the RAM slot (lib.rs:2777-2812), so node tx-time archaeology is impossible pre-substrate; documented, not hidden. `superseded_by` is never set by any write path today (add_edge, lib.rs:2765) — small write-path fix, flagged separately. `recency` = `valid_from`/`recorded_at` **rank**, not a decay curve (a decay constant would be policy). No `RANK BY` ⇒ results return in seed order, engine never reorders — conformance-tested. `epistemic` is cut from the engine vocabulary; callers express it as `prop.<key>` (see ANSWERS A3). Backlinks already work: `TRAVERSE … REL ANY DIRECTION in` (lib.rs:3697).

## Design paths

**Path 1 — Measure-then-mechanism (recommended).** C's skeleton + A's G1 graft. Stage 0 (~0.5 wk): capture the pre-P0 v1 baseline on clean main (**live risk: P0 is uncommitted; merging first destroys the before/after chain**), commit P0, close the fuzz-corpus debt. Stage 1 (1–1.5 wk): grammar+AST above, ~600–900 lines, fuzz generators extended. Stage 2 (2–3 wk): executor — shared-frontier BFS seeded with all K vector hits at once (single visited set; rows carry `(node_u32, min_hops)`, no per-row path clone — kills the O(depth²) clone at lib.rs:3797), inline `is_valid_during`/SYSTEM checks beside `is_valid_as_of`, RRF heap, LIMIT pushdown into the existing-but-unused `NeighborInput.limit` (:3453), var-length in match_pattern **with the currently-missing cycle guard**, NAPI+REST parity (CLAUDE.md drift warning). Stage 3 (1–1.5 wk): **moat-bench** `[[bin]]` + docker-compose Qdrant+Neo4j + embedded LanceDB+Kuzu composition, pre-registered F1–F4 (ANSWERS C1). Stage 4 (1–2 wk): G1 filter pushdown — roaring node-bitmap from WHERE, two-regime switch: |bitmap| ≤ T ⇒ exact-score the bitmap rows; else `search_filter` with a bitmap closure (verified in pinned hnsw_rs 0.3.4: FilterT filter.rs:7, search_filter hnsw.rs:1475 — filtering at result-collection during descent, so ef budget is still spent on filtered-out points; ef inflated by a frozen constant). **T must be sized against warm-LRU/arena residency, not the sidecar**: the off-RAM sidecar's LRU is SIDECAR_CACHE_ROWS = 4096 (lib.rs:1038); a cold brute-force pass at T=4096 is ~4096 positioned reads — hundreds-of-ms class on SATA `⚠ ungrounded: I/O estimate, bench the cold path` — and it evicts the whole cache. Cold-path numbers published separately. Total ~7–9 wk solo; first G3 number at ~week 4. Moves: G3 (primary), G2 (expressibility), G1 (Stage 4).

**Path 2 — Native filter-index engine (Path A full).** Adds persistent `label_idx` + opt-in payload-value roaring bitmaps maintained on every write, giving Qdrant-style payload-index pre-filtering entirely in-memory. Moves G1 hardest. Cost: stated 41–46 dev-days; panel consensus ~1.5–2× that. Risks: write-path tax on the already-losing ingest path; RSS creep; and it **fights the committed S2 substrate direction** (S2 compiles WHERE/OR to SQL over indexed tables) — two filter engines drift unless ownership is decided first. Adopt only the Stage-4 slice above unless the S2 crossover bench says SQL can't hold the hot path.

**Path 3 — Substrate-leveraged (Path B).** Unique genuine wins: `node_versions` append-only projection = the **only** honest route to node tx-time history and `VERSIONS OF`; indexed `DURING`; `count(*)`/anti-join drift aggregates; label anchors replacing match_pattern's full node scan (:3077-3092). But: hard-blocked behind S0 (C-3/HIGH, 4 crash windows — spec file still untracked); per-query SQL on the hot path is planner-by-proxy (HQL latency class becomes SQLite-plan-dependent); and `node_versions` **contradicts shipped WAL compaction** (PR #28 truncates history; the substrate spec demands the projection stay rebuildable — §2.2/§4.3 — while §3.1 keeps SQLite non-authoritative) — unresolvable without an ADR that makes SQLite co-authoritative for history. Sequence: after S0/S1 land, adopt for cold analytics/history only. **Never route the vector or hop path through SQLite** — DuckDB's recursive CTE only reaches 1.09–1.41× of us at deep hops while losing 52× at hop1 (P28/P31); that asymmetry is the governance rule for the native/SQL boundary.

## Recommended path

**Path 1.** It answers the only question that gates everything else — moat or mirage — in ~4 weeks, on shipped infrastructure, with the G1 mechanism deferred until the moat number exists (and then built on a verified crate API, not research). Switch triggers: (a) F1/F2 fire ⇒ stop fused-operator investment past Stage 2; reposition on round-trips + consistency + ops; `RANK BY` survives as ergonomics. (b) F3 fires ⇒ filtering moves to S2 SQL; Stage 4 cancelled. (c) S2 lands first and its crossover bench shows SQL pre-filter within 30% of native bitmaps ⇒ skip Stage 4 entirely, ride the substrate. (d) A real consumer query crosses the planner line (two traverses, search-reseeds-search) ⇒ stop; explicit planner-lite-vs-app-side decision, not drift.

## Planner boundary

Direct dispatch holds while every query is **one linear pipeline, fixed stage order, ≤1 instance per stage, each stage 1:1 to an engine call, and every runtime decision a single frozen-constant comparison**. The exact shapes that force a planner: (1) two seed legs joined (`MATCH…MATCH…`, vector×lexical where either drives) — cardinality estimation; (2) binding selection when a multi-variable pattern feeds a traverse — join choice; (3) filter-vs-expand reordering by cost; (4) OPTIONAL/branching patterns — outer joins; (5) >3 RRF legs with heterogeneous fetch budgets. Containment: those shapes are **parse errors with remedy text**, the fixed order is encoded in the pest rule (repetition is unparseable), and the two heuristic constants (bitmap threshold T, ef inflation) are published, bench-calibrated, and frozen — the moment either becomes adaptive, that is the tar-pit's front door.

## Open risks / what I'd need

1. **No query log.** C1's query set is inferred from SDDs. Need: 2 weeks of MSP/GKS traces before freezing the bench. 2. **Filtered-recall unknown.** No filtered vector benchmark exists anywhere in-repo; the 1–20% selectivity band with result-collection filtering is the open technical risk (F3 gate). 3. **Variance vs margin.** ±5–11% run-to-run variance (P31 §4) plus the ±10% regression envelope (REPORT--HQL-V1-VS-V2 §4.3) make 10% bars unfalsifiable without ≥3 runs + pre-registered criteria — bench discipline is load-bearing, not bureaucracy. 4. **S1 expiry.** Props leave RAM at S1; the WHERE-closure path must read through the same accessor the substrate will own, or Stage 4 gets rebuilt. Need: filter-ownership ADR now. 5. **History ADR.** WAL compaction vs node version history vs projection rebuildability — three committed decisions, mutually inconsistent; `VERSIONS OF` waits on it. 6. **`superseded_by` unwired** (lib.rs:2765) — SYSTEM-axis semantics are only as good as this write-path fix. 7. **Cold sidecar I/O** — Regime-A latency claims hold only warm or f32-resident; publish cold separately. 8. **Pipeline consistency contract** — read-committed-per-stage; document before a consumer reports it. 9. **Credibility ceiling** — every number is maintainer-run Level 0/1; the moat claim needs one external Level-2 reproduction more than it needs another decimal place. 10. **Text leg absent until S3** — the 4-layer GoVibe cascade fuses in-engine only after FTS5 lands; until then `RANK BY` fuses vector/graph/temporal/prop signals only — said plainly in the spec.
