## G-R3.1
**Verdict:** Strengthens — a *different and more durable* rationale than latency, because it survives F1 (the latency-mirage falsifier). And it is directly measurable: tokens-to-equal-quality.
**Reasoning:** Round 1's G3 bet was latency-led (~1.5–2.5×, unmeasured) with F1 pre-committing a downgrade on a tie. The scarcity argument changes the currency: for a VRAM-evicted 2–4B worker (the brief's fleet sizing) the scarce resource is *context window*. App-side fusion pushes three raw, duplicate-bearing lists through the worker's prompt; DB-side `RANK BY rrf` sends one fused, deduplicated top-K. That is latency-independent — a tie doesn't touch it — and lands on surface already designed: the `CONTEXT … BUDGET n` bounded Virtual Document (retrieve_context, lib.rs:4257) is context-budget-shaped output. Honesty checks: (1) the models *disagree* — the worker (slack regime) rejects in-engine fusion as harder to cache/debug; the orchestrator (constrained) wants it. That is the tier boundary, confirming Round 2's split: two of the worker's three tools already exist as primitives (hybrid_search; O(1) interned-id get; keyword-search arrives with S3 FTS5 — today's trigram is fuzzy-id-only) — MCP plumbing, not HQL. HQL/G3 is orchestrator surface. (2) A small model saying what it wants may be anthropomorphized training echo. *Measurement:* fixed task suite; arm A = worker fuses 3 raw lists in-context, arm B = one DB-fused top-K; measure retrieval tokens per task and quality at a fixed context budget. Prediction: ~2–3× token cut at equal recall `⚠ hypothesis — dedup across legs is the mechanism`; also test the worker's counterclaim (three cacheable calls win on repeated queries). Add **F-token**: <1.3× savings at equal quality ⇒ the scarcity rationale joins latency in the mirage bin.
**Would change my mind if:** raw-list redundancy proves negligible (tiny K per leg), or per-leg provenance *helps* weak reasoners — then fusion is convenience, not a resource win.

## G-R3.2
**Verdict:** The tension is real: today the engine does **not** deliver snapshot isolation, and nodes lose version history in RAM — SQLite WAL is honestly better on that axis. But the orchestrator's stated needs (versioned state, point-in-time, lost-update protection, an audit trail for failed runs — which I operationalize as *what changed since my eviction, as of clock X*) map onto shipped-but-unexposed machinery. Closing that is S/M; full MVCC is L and I refuse it.
**Reasoning:** What the code gives: (a) DashMap-concurrent core — per-entry atomicity, no multi-key consistent view; a BFS interleaved with writes reads torn state (read-committed, flagged in Round 1). (b) REST is *stricter than the engine*: `Arc<RwLock<Storage>>` (router.rs:26), `.write()` on every mutating handler (:172–:315) — each write excludes all readers across the durable persist, fsync-bound `⚠ lock-hold unmeasured — bench it` — while NAPI wraps bare `Arc<Storage>`. (c) Versioned reads are asymmetric: edges retain history (forward-dated retraction keeps past `AS OF` stable; a *backdated* one mutates `valid_to` in place and changes history answers `⚠ untested semantics`); nodes do not — `supersede_node` overwrites the RAM slot (lib.rs:2777-2812). (d) Single-writer-per-file by construction (one WAL writer thread; second-process file-lock UNVERIFIED) — matching the real topology: agents are MCP/REST clients of one server. SQLite WAL gives every reader a stable snapshot — concede that axis. But the stated requirements already exist in-engine, with one caveat: an append-only signed event log (the WAL — truncated at each checkpoint by shipped compaction, hence the ADR below), Lamport-clocked `SignedEvent`s, **`events_since(from_clock)` (lib.rs:5393)** — literally "what did agent B leave since clock X" — `reconcile_state` (:4115) for LWW lost-update handling, Merkle root (:5314). None exposed: no `/v1/sync/*` route (Round 2). Measured comfort: shadow-sync-stress ran 12 writers + 4 readers at 118 TPS, p95 432 µs, on an HDD (AUDIT--P14) — a 3–8-agent fleet sits far below that. *Cost to close:* **S** — expose `events_since`/Merkle/checkpoint over REST+MCP; write the consistency-contract doc. **S/M** — REST `RwLock` → `Arc<Storage>` after a fleet-shaped bench row. **M** — wire edge `superseded_by` (never set, lib.rs:2765) and, separately, node history via a `node_versions` projection (PROPOSAL Path 3, substrate-gated); both force the WAL-compaction-vs-history ADR, now urgent. Once S0/S1 land, SQLite-projection reads under WAL mode would be snapshot-isolated — audit reads get real snapshots while the hot path stays native read-committed. **L, refuse** — in-engine MVCC: the storage-engine twin of the planner tar-pit.
**Would change my mind if:** real fleet traces show same-key write-write conflicts at rates where LWW visibly loses updates — then append-discipline isn't enough and the M-item (or SQLite as coordination store) must lead.

## G-R3.3
**Verdict:** Path 1's skeleton survives; its tail inverts — fusion + bitemporal audit + concurrency surface up; G1 filter pushdown and the Cypher head-to-head down.
**Reasoning:** *Up:* (1) `events_since` + checkpoint exposure over REST/MCP — S, built, unexposed; the cheapest orchestrator feature in the codebase. (2) Bitemporal audit correctness (edge `superseded_by` fix, two-axis `AS OF`) — promoted to headline: the orchestrator named WAL + point-in-time snapshot as the requirement and the audit trail for failed runs (brief R3), and it is our only axis no embedded competitor ships (Round 2). (3) The WAL-compaction-vs-history ADR + `node_versions` — scratchpad archaeology is node history. (4) Fleet-shaped concurrency bench (3–8 writers, checkpoint payloads, concurrent `AS OF` readers, p99 under write load), then the `RwLock`→`Arc<Storage>` change if readers stall. (5) F-token as a first-class moat-bench axis. (6) Worker-tier MCP tools — three primitives, no HQL. *Down:* (1) G1 filtered-ANN pushdown — a 500-episode worker doesn't need it; the orchestrator isn't QPS-bound; defer behind F-token. (2) The HQL-vs-Cypher bench — state-graph reads look depth-1–2 shallow `⚠ inferred from the brief's dependency/milestone framing; no traces`; keep P1 var-length for GoVibe's H-scale, drop its bench urgency. (3) Residual Qdrant-latency framing. *Unchanged:* Stage-0 baseline discipline; the minimal pipeline + caller-parameterized `RANK BY` (it *is* the orchestrator surface); `WIDTH`/`BUDGET` — the token-budget knobs the scarcity rationale needs. **OPEN-QUESTIONS:** (a) does Rwang/GoVibe checkpoint agent state to a DB today, or to flat files? Instrument one real fleet run first. (b) Real scratchpad size/cadence for bench payloads. (c) gemma's "exponential" race growth is rhetoric `⚠ ungrounded — measure conflict rate vs fleet size`.
**Would change my mind if:** traces show orchestrator state fits happily in flat JSON with no concurrent-write pain — then the orchestrator buyer is also a mirage at current fleet sizes, and the worker's three-tools MCP story is the only demand-backed surface.

## G-R3.4
**Verdict:** The CRDT core is real, shipped algebra — but phone↔cloud production-ready it is not. It is a unit-tested prototype with no transport, no FFI exposure, no curated export, no conflict UX, and an untested compaction×delta interplay. The "sleeper asset" is the algebra; the product around it does not exist yet.
**Reasoning:** *Genuinely shipped:* `reconcile_state` (lib.rs:4115) — per-event ed25519 verification against registered peer keys (`verify_event_signature`, :2481; unknown peer ⇒ reject), per-entity LWW by Lamport clock, atomic clock merge via CAS, embedding replay (vectors sync, not just rows), durable persistence of accepted remote events; Merkle root (:5314) for divergence detection. That matches Model 3's LWW ask almost verbatim. *Maturity:* three unit tests (tests/crdt_sync_tests.rs — LWW resolution, clock convergence, forgery rejection), single-process; the convergence test *bypasses* signature verification via `local_peer_id` (:181-187). The gossip layer is a Mark VIII blueprint (SRD/TDD only), unimplemented. *Missing, itemized:* (1) transport — none in any direction (S/M); (2) FFI — **zero sync entry points**: the MARK XVI C ABI is 8 symbols (open/close/add_node/search/execute_hql/retrieve_context/flush_index/free_string, src/ffi.rs) — a phone cannot call `events_since`/`reconcile_state` today (S); (3) **curated export — the flagship's core demand has no API**: `events_since` (:5393) returns *every* event past a clock — no per-collection/label/predicate selection, no redaction hook; selective-sync policy is new privacy-bearing design surface, the piece to get right first (M); (4) conflict UX — LWW is silent; rejected events `println` and vanish (:4124-4128); "flag unresolvable for review" needs a conflict-journal API (S/M); (5) compaction × delta sync untested — `events_since` scans the live WAL, which checkpointing rewrites to live-state; an offline-across-checkpoint peer gets current-state-since-clock, plausibly LWW-convergent but intermediate versions are gone and tombstone semantics unverified — zero tests (S to test); (6) `events_since` is a full-WAL scan + per-line JSON parse per call, no clock index — battery-hostile (S/M); (7) iOS is still a stub (MARK XVI B-1). *Competitive honesty:* on the sync axis, cr-sqlite/PowerSync/Turso embedded replicas are mature `⚠ not re-verified this round`; our differentiator is *what* syncs — a bitemporal graph+vector store — not sync-tech maturity. *Cost to a credible phone↔cloud beta:* an M-class program ≈ 4–8 weeks solo `⚠ estimate`; production (key-exchange/trust bootstrap, battery-grade deltas, cross-platform soak) sits beyond it.
**Would change my mind if:** a two-device pilot (Android ↔ server over a trivial HTTP shuttle) converges cleanly across a compaction checkpoint and a week of intermittent connectivity — that upgrades "prototype" to "beta-able".

## ROUND3 verdict:
Weighted as roleplay, the evidence *strengthens* G3 with a latency-independent rationale (context-token economics, falsifiable as F-token), *exposes* a real gap (no snapshot isolation; node history lost in RAM — SQLite WAL wins that axis today; the cheap fix is exposing shipped `events_since`/WAL/Lamport machinery — plus, once S0/S1 land, the substrate's snapshot-isolated projection — not building MVCC), *reorders* Path 1 (bitemporal audit + concurrency surface + token metric up; G1 pushdown + Cypher bench down), and *tempers* tier-C excitement (the CRDT algebra is real and matches Model 3's LWW ask, but phone↔cloud is a prototype missing transport, FFI exposure, curated export, and conflict UX — an M-class program, not a flipped switch); most important next act: **one real orchestrator trace (Rwang/GoVibe) + the token-cost A/B — the buyers and both new rationales are still hypotheses spoken by small models.**
