## name

Path C — Minimal-Delta Contract Surface (HQL v2.5: one fixed-shape pipeline suffix, zero planner)

## thesis

The three targets are not blocked by missing query-engine machinery; they are blocked by (a) a grammar that cannot express what the engine already executes in microseconds, and (b) the absence of any G3-shaped measurement. So: ship the smallest grammar delta that makes G1/G2/G3 *expressible* — boolean WHERE (OR/NOT/parens), var-length paths, WIDTH fan-out caps, two-axis AS OF + DURING interval overlap, and exactly ONE composite command shape (vector-seed THEN TRAVERSE, AS OF, RANK BY rrf) — compiled by direct dispatch into a fixed 4-slot struct executed by straight-line code, exactly like `execute_hql` today (src/lib.rs:3354-3500). The only real engine work is three surgical hot-path items: predicate pushdown with adaptive refetch inside `hybrid_search` (fixes the post-filter recall bug at lib.rs:2927), a shared-frontier traverse stage that carries (node_u32, min_hops) instead of cloning full `Vec<EdgeOutput>` paths per row (the O(depth²) clone at lib.rs:3797), and an RRF executor over ranked lists. Everything saved goes into the C1 moat benchmark harness — because G3 is won by round-trip arithmetic (1 in-process call vs >=3 network hops + app-side join) and by a consistency property app-composition structurally cannot have (one AS OF timestamp applied to both the vector post-filter at lib.rs:3633 and every edge check at lib.rs:3754), not by exotic execution. This path deliberately does NOT build: a logical planner/EXPLAIN, filter-aware HNSW graph pruning (ACORN), branching/OPTIONAL patterns, aggregations beyond count(*), text-query seeds (gated on substrate S3 FTS5 per docs/PLAN--HQL-REFINEMENT.md P3), or node-version history (impossible from RAM today — supersede_node overwrites the slot, lib.rs:2777-2812; deferred to SQLite S1/S2). For a solo-maintained ~6k-line engine, every one of those is a tar-pit with a cheaper honest substitute.

## grammar_sketch

Delta over working-tree src/query/hql.pest (94 lines today). New/changed rules:

```pest
// WHERE becomes a boolean expression (SPEC--HQL-V2 §4.1 + NOT):
expr      = { term ~ (^"OR" ~ term)* }
term      = { factor ~ (^"AND" ~ factor)* }
factor    = { (^"NOT")? ~ (predicate | "(" ~ expr ~ ")") }
where_clause = { ^"WHERE" ~ expr }                    // replaces flat AND list (hql.pest:40)
in_list   = { field ~ ^"IN" ~ "[" ~ filter_value ~ ("," ~ filter_value)* ~ "]" }  // predicate alternative

// Temporal (replaces hql.pest:25):
as_of     = { ^"AS" ~ ^"OF" ~ string_lit ~ (^"SYSTEM" ~ string_lit)? }
during    = { ^"DURING" ~ string_lit ~ ^"AND" ~ string_lit }
temporal  = { as_of | during }

// Traversal bounds (W-scale + hop interval):
width       = @{ ASCII_DIGIT+ }
width_spec  = { ^"WIDTH" ~ width }
depth_range = { depth ~ (".." ~ depth)? }             // DEPTH 2 or DEPTH 1..3
traverse    = { ^"TRAVERSE" ~ ^"FROM" ~ seed ~ ^"DEPTH" ~ depth_range ~ ^"REL" ~ rel
                ~ width_spec? ~ direction_spec? ~ temporal? ~ clauses }

// Var-length in patterns (SPEC--HQL-V2 §3.1) + edge alternation:
var_len    = { "*" ~ depth ~ ".." ~ depth }
rel_detail = { "[" ~ pat_var? ~ (":" ~ rel_type)? ~ var_len? ~ "]" }   // rel_type reuses a|b union (hql.pest:9)

// THE one composite shape (G3). No repetition, no reordering — fixed slots:
signal      = { (^"vector" | ^"hops" | ^"recency") ~ ":" ~ number }
rank_clause = { ^"RANK" ~ ^"BY" ~ ^"rrf" ~ "(" ~ (^"k" ~ ":" ~ k ~ ",")? ~ signal ~ ("," ~ signal)* ~ ")" }
trav_stage  = { ^"THEN" ~ ^"TRAVERSE" ~ ^"REL" ~ rel ~ ^"DEPTH" ~ depth_range ~ width_spec? ~ direction_spec? }
pipeline    = { (search | hybrid) ~ trav_stage ~ temporal? ~ rank_clause? ~ clauses }

tier  = { "H0".."H6" }                                 // adds H6 (STD-Execution-Governance §3)
query = { SOI ~ (pipeline | search | traverse | match_pattern | hybrid | context) ~ EOI }
```

Example queries:
1. G1 vector+filter: `SEARCH doc-tax-2026 K 10 EF 200 IN gks WHERE (prop.status = "active" OR prop.status = "review") AND NOT prop.tier = "H0"`
2. G2 var-length (makes the P26/P30 bench query native): `MATCH (a {id:"FEAT--TAX-DEDUCT"})-[:LINK*1..3]->(b) WHERE b.prop.kind = "spec" RETURN b.id LIMIT 1000`
3. W-scale + interval overlap: `TRAVERSE FROM ROADMAP-42 DEPTH 1..3 REL depends_on|blocks WIDTH 8 DIRECTION both DURING "2026-06-01T00:00:00Z" AND "2026-07-01T00:00:00Z"`
4. Two-axis bitemporal: `TRAVERSE FROM task-77 DEPTH 2 REL assigned_to AS OF "2026-06-15T00:00:00Z" SYSTEM "2026-06-20T00:00:00Z"`
5. Backlinks (gks_backlinks, already expressible — document it): `TRAVERSE FROM atom-9 DEPTH 1 REL ANY DIRECTION in` ("ANY" = no-filter sentinel, lib.rs:3694-3710)
6. G3 moat pipeline: `MATCH audit-seed ALPHA 0.0 K 40 IN gks THEN TRAVERSE REL depends_on|caused_by DEPTH 1..2 WIDTH 8 DIRECTION out AS OF "2026-07-01T00:00:00Z" RANK BY rrf(k:60, vector:1.0, hops:0.5, recency:1.2) LIMIT 20`
(Seed is a node-id or SIMILAR TO literal vector — text seeds stay gated on substrate S3 FTS5; `epistemic` signal is CUT: no grounded signal source exists once K-Impact goes, and inventing one violates the domain-neutral guardrail.)

## g1

Mechanism, two halves. (1) Expressiveness is a grammar problem: Qdrant's filter DSL is must/should/must_not + match/range/values-in — which maps exactly to AND/OR/NOT + =/</<=/>/>= (hql.pest:37) + the new IN-list. After the WHERE upgrade we have parity minus geo filters and nested-array payload paths (declared non-goals; GoVibe's ERD has neither). (2) Latency is one engine change, not a planner: compile the WHERE expr to a `Fn(&NodeOutput) -> bool` closure and pass it into `hybrid_search` as a candidate predicate applied at the metadata-join step (lib.rs:3626-3656), with adaptive refetch — start at fetch = k*oversample (existing knob, lib.rs:3558-3567), and if filtered survivors < k, double fetch (and ef) and re-search, bottoming out in the exact-brute-force escape hatch that already exists (lib.rs:3576-3596). No HNSW-internal changes. VERDICT: reachable with an asterisk. Against Qdrant-as-actually-deployed (Docker server, gRPC), the >=10% latency win is very likely — P20 measured GB 974 µs p50 vs Qdrant 3,301 µs unfiltered, and the round-trip tax is structural — but NO filtered comparison exists in-repo (AUDIT--P20 gap explicitly flagged in grounding) and no embedded-fair Qdrant harness exists at all. At low filter selectivity (<~10% pass rate) post-filter+refetch will lose recall or latency to Qdrant's filter-aware HNSW; the brute-force floor caps the damage but does not win. Honest target: parity-or-better at selectivity >=10%, published selectivity curve below that. Recall claims must use the P32/P33 protocol (exact-L2 ground truth, real bge-m3 corpus).

## g2

Mechanism: G2 is scoped to the 3-4 shapes GoVibe actually calls (SDD-GoVibe-MSP-GKS-Integration §3): (a) query_genesis_graph = k-hop bounded expansion with fan-out cap → TRAVERSE DEPTH 1..d WIDTH w (WIDTH = per-node candidate-eid cap inside the BFS loop at lib.rs:3737-3747, sorted by edge key before truncation for determinism); (b) gks_backlinks → TRAVERSE DEPTH 1 DIRECTION in REL ANY (already executable, lib.rs:3713-3719); (c) gks_lookup → interned-id point read (already O(1)); (d) the Cypher-equivalence shape → var-length `-[:R*min..max]->` implemented as a frontier loop in `match_pattern`'s hop expansion (lib.rs:3095-3168) with a per-path visited set (grounding: match_pattern currently has NO cycle guard — var-length makes one mandatory). Plus two free wins: LIMIT pushdown into the BFS early-exit that already exists but HQL never uses (`NeighborInput.limit`, hardcoded None at lib.rs:3453, early-return at 3805-3809), and lazy rows — pipeline/traverse rows carry (node_u32, min_hops) and materialize full node JSON only for the final LIMIT rows, killing the payload-confound flagged in AUDIT--P29/P31 and the per-row path-clone at lib.rs:3797-3798. VERDICT: the latency half of G2 is not merely reachable, it is already exceeded — P31/P30 measured GB 120-189x FASTER than Neo4j/Kuzu/LadybugDB at hop1, 6.8-10.5x at hop3, ~23x at hop6 (variance-caveated); "<=10% slower" is the wrong bar to advertise. What is genuinely at risk: (1) after var-length lands, the first true HQL-vs-Cypher head-to-head (REPORT--HQL-V1-VS-V2 §4.4) could shrink margins once both sides return bare ids — lazy rows exist to protect this; (2) expressive equivalence holds only for linear paths + var-length + count(*) — no OPTIONAL MATCH, shortest-path, or aggregation; claim "Cypher subset sufficient for GoVibe's shapes", never "Cypher-equivalent"; (3) the standing losses are ingest (48-60x, durable WAL vs COPY) and RSS (~7x) — if G2 silently includes those, it is NOT reachable in this path; renegotiate G2 to read-path explicitly (ingest is substrate-S1/bulk-path territory).

## g3

Mechanism: the `pipeline` command executes seed→traverse→temporal→rank in ONE in-process call. Execution (`execute_pipeline`, new fn beside execute_hql in src/lib.rs): (1) `hybrid_search` for K seeds (alpha=0 vector rank recorded per row); (2) ONE shared-frontier BFS seeded with all K node_u32s at once (single visited HashSet, out_idx/in_idx from lib.rs:1556-1559, rel-union filter per lib.rs:3694-3710, WIDTH cap, per-edge `is_valid_as_of`/`is_valid_during` using the SAME timestamp as the seed stage's post-filter) recording min_hops per reached node — not K separate `neighbors` calls, and no path materialization; (3) RRF: score(n) = Σ w_s/(k_rrf + rank_s(n)) over caller-named signals — vector = seed rank, hops = min_hops order, recency = valid_from (or recorded_at with SYSTEM) descending; weights 100% caller-supplied, no RANK BY → plain concat (engine never imposes policy); (4) existing `apply_hql_clauses` (lib.rs:2927). Round-trip arithmetic vs app-composition (Qdrant gRPC + Neo4j bolt + app-side RRF, the exact gks_recall shape from CONCEPT--HYBRID-RETRIEVAL-FTS-LAYER): composition pays >=3 network round-trips + 2 serializations + a client id-join; its floor is Qdrant's own 3.3 ms p50 (P20) plus Neo4j's ~2.7-4 ms hop1 (P23) plus join — >=6-8 ms p50, worse p99. Our estimate: ~1 ms seed (P20) + low-single-digit-ms shared-frontier 2-hop from 40 seeds (hop1 is 22.6 µs/seed class, P31) + trivial RRF ≈ 2-4 ms, one call. And one thing composition CANNOT do at any latency: a consistent AS OF snapshot across the vector and graph dimensions — Qdrant and Neo4j have no shared time axis; we apply one timestamp at lib.rs:3633 and lib.rs:3754. VERDICT: reachable with high confidence on round-trips (structural, 1 vs >=3) and very likely on latency, but per guardrail 3 it is a HYPOTHESIS until the C1 moat harness runs — no G3-shaped benchmark has ever been executed (grounding report 4 explicitly: "No cross-dimension benchmark has ever been run"). The harness (new [[bin]] `moat-bench` behind the bins feature + docker-compose Qdrant+Neo4j baseline, Level-1 discipline from benchmark/) is therefore a deliverable co-equal with the grammar. Honest fallback if colocated async-pipelined composition ties on p50: the decisive claim narrows to round-trips + p99 + cross-dimension AS OF consistency + zero ops — with numbers, per guardrail 6.

## interval_semantics

Syntax: `AS OF "<t>"` = valid-time point projection (existing semantics: valid_from <= t < valid_to, lexicographic RFC3339 compare in `is_valid_as_of`, lib.rs:3502-3514). `AS OF "<t>" SYSTEM "<t2>"` = adds tx-time: edge visible iff recorded_at <= t2 (EdgeOutput.recorded_at, lib.rs:156-169). Honest scope cut: (a) `superseded_by` is never set on any write path (add_edge sets None, lib.rs:2765), so tx-time is append-monotone "known-by-t2" — correct for GoVibe's ERD where state records close via supersession chains, but supersession-aware tx-time waits until something writes the field; (b) nodes carry NO recorded_at (NodeOutput, lib.rs:121-138) — SYSTEM applies to edges only, documented as such, no silent lies. `DURING "<a>" AND "<b>"` = valid-time interval OVERLAP: entity valid interval [valid_from, valid_to) intersects [a,b), i.e. valid_from < b AND (valid_to IS NULL OR valid_to > a) — implemented as `is_valid_during`, a sibling of is_valid_as_of using the same string comparison, evaluated at the identical three sites (hybrid_search post-filter lib.rs:3633, neighbors per-edge/per-node lib.rs:3754/3789, match_pattern lib.rs:3120/3151). No temporal index — per-row compare is the existing cost model and is fine at GoVibe scale (hundreds to 100k atoms); build an index only if moat-bench says so (guardrail 3). Hop-interval / H-scale: `DEPTH <min>..<max>` returns nodes whose BFS hop distance falls in [min,max] (plain `DEPTH d` = 1..d, backward compatible); `WIDTH <n>` = per-node per-hop expansion cap enforcing STD-Execution-Governance §4 W-scale (W2=3-5, W3=6-8, W4=9+ — caller passes the number, engine enforces mechanically, stays domain-neutral); CONTEXT tier extends to H6 (STD §3 ceiling; ScalingTier::parse at lib.rs:182-204 gains one arm, hops=6). Retracted-edge visibility stays AS-OF-only from HQL (include_invalid remains REST/NAPI-only, lib.rs:3452) — time-travel is the query surface, resurrection is an ops surface.

## planner_line

Direct dispatch holds exactly as long as every query is a LINEAR composition with at most one instance of each stage in one fixed order: seed(vector) → traverse → temporal-projection → rank → post-clauses. It breaks — and a planner becomes unavoidable — the moment any of these appear: (1) two or more traverse stages or a traverse whose output re-seeds another search; (2) joins/branches between two result sets (OPTIONAL MATCH, tree patterns, set-difference like the drift anti-join in SDD-Symbol-Graph §6); (3) cost-based reordering (deciding filter-before-hop vs hop-before-filter from cardinality); (4) grouped aggregation. This design stays inside the line by CONSTRUCTION, not discipline: the pest `pipeline` rule admits exactly one optional `trav_stage`, one optional `temporal`, one optional `rank_clause` — repetition is a parse error, so the executor is a straight-line function over a fixed struct `PipelineSpec { seed, traverse: Option<TravStage>, temporal: Option<Temporal>, rank: Option<RankSpec>, clauses }`, the same shape as today's HqlCommand match (lib.rs:3399). When S3 lands text search, "text+vector fused by rrf" is added as a SECOND fixed shape (two seed lists → rrf), still no plan tree. Anything past the line gets an explicit named parse error ("not expressible; compose at the application layer") — honesty over ambition, and the app-composition escape hatch is precisely what moat-bench measures us against.

Stage 1 (1-1.5 wk): grammar+AST — WHERE expr (OR/NOT/parens/IN-list), var-length + rel-alternation in patterns, DEPTH range, WIDTH, H6, AS OF SYSTEM, DURING, pipeline+RANK BY rules; ~600-900 lines across hql.pest/ast.rs + extended fuzz generators; zero engine risk. Stage 2 (2-3 wk): engine — predicate-closure pushdown + adaptive refetch in hybrid_search; shared-frontier traverse stage with lazy (node_u32, min_hops) rows; var-length frontier in match_pattern with cycle guard; is_valid_during + SYSTEM checks; RRF executor; LIMIT pushdown; wire BOTH surfaces (NAPI method + REST route, CLAUDE.md parity warning). Stage 3 (1-1.5 wk): moat-bench [[bin]] + docker-compose Qdrant+Neo4j composition baseline + a filtered-vector bench row (the G1 evidence gap), Level-1 reproducibility discipline from benchmark/. Stage 4 (1-2 wk): measure-and-optimize loop strictly profile-guided (refetch policy tuning, materialization audit); no speculative optimization. Effort deliberately NOT spent: planner/EXPLAIN (weeks-to-months), filter-aware HNSW (research-grade), text seeds (S3's job), node version history (S1/S2's job).

## risks

(1) Filtered-ANN at low selectivity: adaptive refetch degrades toward brute force below ~10% selectivity — G1 could publicly lose that regime to Qdrant; mitigated by publishing the selectivity curve and the brute-force floor, not by hiding it. (2) Variance vs margin: the >=10%/<= 10% bars live inside the repo's own ±10-11% run-variance envelope (P31 §4: Kuzu hop6 doubled between identical runs) — a "10% win" is barely measurable; pin >=3 runs, p50+p99, and pre-registered pass criteria or the targets are unfalsifiable. (3) All evidence is Level 0/1 maintainer-run on one Windows box (INDEPENDENT-BENCHMARKS.md: zero external reproductions) — competitive claims stay soft until someone else runs moat-bench. (4) Pipeline quality sensitivity: RRF output depends on seed K and rrf-k; caller-parameterized by design, but bad defaults will be blamed on the engine — ship measured recommended values, not hardcoded ones. (5) Substrate collision: S2 plans to compile WHERE/OR to SQL over the SQLite projection while this path builds a native predicate closure — deliberate duplication (native closure = hot vector/pipeline path; SQL = cold analytics/count) must be documented in the ADR or it will look like drift. (6) Baseline-capture window: P0 is uncommitted; if it merges before the v1 baseline run, the before/after comparison is lost forever. (7) Grammar creep: once THEN TRAVERSE exists, pressure for THEN THEN/joins begins — the parse-error-past-the-line policy must be enforced in review, or the planner tar-pit arrives through the back door. (8) hybrid_search re-search on refetch doubles HNSW work in the worst case — measure before accepting; fallback is single-shot fetch with a larger static multiplier.

## honest_assessment

Where the bars are NOT honestly reachable as written: G1 — "match Qdrant DSL expressiveness" is reachable only minus geo filters and nested-array payload matching (declared non-goals; GoVibe needs neither), and the >=10% latency win is only defensible against Qdrant-as-deployed (server+gRPC) — no embedded-fair Qdrant exists to compare against, and below ~10% filter selectivity we will likely NOT match filter-aware HNSW; fallback: claim parity at selectivity >=10% with a published curve and the disclosed embedded-vs-server framing P20 already uses. G2 — the "<=10% slower" latency bar is already beaten by 1-2 orders of magnitude on every measured shape, but ONLY for read-path linear traversals; if G2 is read as full Cypher equivalence or as including ingest/RSS, it is not reachable in this path (ingest loses 48-60x, RSS ~7x — that is substrate-S1 and bulk-load territory, renegotiate scope explicitly). Supersede-chain/version-history queries (GoVibe ERD demand #2) are NOT deliverable at all pre-SQLite-S1 because historical node versions exist only in the WAL (lib.rs:2777-2812) — say so now, not at integration time. Tx-time AS OF ships edges-only and supersession-blind (nothing sets superseded_by, lib.rs:2765) — a documented honest subset, not full bitemporality. G3 — the round-trip win is structural and the AS-OF-consistency win is absolute, but the LATENCY "decisive win" is an unmeasured hypothesis (no G3 benchmark has ever been run); if colocated composition ties on p50, the honest moat is round-trips + p99 + cross-dimension snapshot consistency + zero-ops embedded deployment, and the mission's own contract says to report that renegotiation rather than massage the numbers.

## switch_trigger

Abandon or escalate this path on any of: (1) MOAT MIRAGE — moat-bench shows a colocated, async-pipelined Qdrant+Neo4j+app-RRF composition matching or beating the single-call pipeline on BOTH p50 and p99 at GoVibe-scale data (~100k nodes/800k edges, K=40, depth 2): the G3 premise is false; pivot positioning to embedded/ops/consistency and stop selling latency. (2) G1 FLOOR MISS — after Stage 4 tuning, filtered search cannot reach Qdrant recall@10 parity at >=10% selectivity without >2x latency: post-filter+refetch is architecturally insufficient and real filter-aware HNSW (ACORN-class, inside hnsw_rs or a fork) is required — that exceeds minimal-delta scope and forces an explicit G1 renegotiation or a Path-B-style engine investment decision. (3) SHAPE INSUFFICIENCY — the first real GoVibe/GKS integration produces a load-bearing query needing >=2 traverse stages, a join between two searches, or grouped aggregation (i.e., anything past the planner line): the fixed-shape bet is wrong for the actual consumer and the planner-lite alternative must be reopened deliberately rather than bolted on. (4) BASELINE LOST — if the pre-P0 v1 baseline cannot be captured before P0 merges, the refinement program loses its before/after evidence chain; that doesn't kill the design but voids every "no regression" claim, so freeze merges until Stage 0 runs. Each trigger is an evidence event, not a vibe — consistent with guardrail 6.
