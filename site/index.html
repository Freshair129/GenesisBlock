Why it matters

Teams keep maintaining SQLite, graph, and vector systems separately, then lose consistency between them.

Head to head audit.
Use the sharpest facts.

The strongest story is not "we win everywhere." The strongest story is "we know exactly where we are strong, where we are tied, and where we still lose today."

Graph latency / embedded graph+vector ~168x vs LadybugDB

Measured on hop1 latency with full node payload at 100k. This is the closest on-niche head-to-head in the current report.

Traversal / server graph 7-185x vs Neo4j

Use this when the room frames Neo4j as the reference point, but be clear that part of the gap is the embedded-versus-server tax.

Vector point-query p50 / embedded vector ~9x vs LanceDB

The current repo report records 935.6 us vs 8,392 us at matched recall bands in the 100k vector setup.

Vector search / industry references Recall parity with Chroma ~3.4x

Recall@10 is 0.979 vs 0.981 for Chroma, while query p50 is 974 us vs Qdrant's 3,301 us in the 100k three-way audit.

Proof and caveats

Say the wins cleanly. Keep the caveats visible.

The audit already gives you both. That makes the story stronger, especially in technical rooms that will immediately ask what the comparison leaves out.

Measured wins GenesisBlockDB is strongest when the job is low-latency agent memory across graph and vector semantics.

That is where the embedded architecture and one-boundary model show up as real user-facing speed, not just elegant architecture slides.

Honest caveats Bulk ingest and RAM efficiency are still weaker than the columnar or KV-heavy comparators.

Today the report explicitly shows losses on bulk ingest versus Kuzu, LadybugDB, DuckDB, and RocksDB-oriented baselines.

What to emphasize The differentiator is not any one subsystem. It is the combined boundary.

Relational projection, graph identity, vector retrieval, provenance, and a governed durability model all stay attached to one engine contract.

  • Use `7-185x vs Neo4j` only with the note that Neo4j is a server graph comparison, not an embedded-embedded comparison.
  • Use `~9x vs LanceDB` specifically for point-query vector p50 at the measured recall band, not as a broad blanket claim.
  • Use `Recall parity with Chroma` for quality framing and `~3.4x p50 vs Qdrant` for latency framing; they answer different questions.
  • Avoid claiming RocksDB is a broad loss or broad win. The clean statement in the report is that hop1 is effectively tied while the deeper payload comparison is not apples to apples.
